# Geospatial Open Data

> ANBU OSINT Division 002 — Collection Tradecraft

## Purpose

Covers collection and analysis of geospatial open data: administrative boundaries, infrastructure, elevation, land use, and points of interest.

## Scope

Open geospatial datasets from national mapping agencies, OpenStreetMap, government portals, and international organizations.

## Intelligence objectives

- Build geographic frameworks for analysis
- Map infrastructure, boundaries, and points of interest
- Analyze spatial relationships and patterns
- Provide basemaps for imagery and event analysis

## Core concepts

- Vector versus raster data
- Coordinate reference systems
- Administrative boundary hierarchies
- OpenStreetMap as crowdsourced geographic data
- Geocoding and geolocation accuracy

## Analytical methodology

Identify relevant geospatial datasets for the area and question. Use official sources where available; OpenStreetMap for global coverage. Standardize coordinate systems. Perform spatial analysis (overlay, proximity, density). Validate against ground truth where possible. Document data sources, dates, and licenses.

## Step-by-step workflow

1. Define area of interest and analytical question
2. Identify geospatial data sources
3. Acquire and standardize datasets
4. Perform spatial analysis
5. Validate against ground sources
6. Document with source citations

## Data requirements

Area of interest; analytical question; required data layers; coordinate system preferences.

## Approved public sources

- National mapping agencies and cadastral data
- OpenStreetMap
- Government open data portals
- UN OCHA and humanitarian data
- OpenTopography and elevation data
- Natural Earth and global datasets

## Source verification standards

Every source is evaluated for authority, proximity to the event or subject, currency, and internal consistency before its content is used analytically. Primary sources are preferred over secondary accounts. Where sources conflict, the conflict is preserved and reported rather than silently resolved. Source reliability is rated on the ANBU reliability scale and recorded in the collection log.

## Analytical framework

Geospatial data provides the geographic framework. Accuracy varies by source; official sources are preferred for boundaries, OpenStreetMap for POIs. Spatial analysis results are validated against ground sources where possible.

## Evidence requirements

Every analytical claim must be traceable to a logged collection item. Evidence requirements: (1) verbatim quotation or precise paraphrase with page/section reference; (2) source attribution including URL or archive identifier; (3) collection timestamp; (4) access method; (5) confidence grade per the ANBU scale. Claims without logged evidence are marked INSUFFICIENT and excluded from analytical products.

## Confidence assessment

HIGH: multiple independent primary sources, direct documentation, no material contradictions. MODERATE: credible sources with minor gaps or single-source primary documentation. LOW: indirect, derivative, or partially corroborated reporting. INSUFFICIENT: evidence does not support a judgment; collection gap or contested sources prevent assessment.

## Common analytical mistakes

- Using outdated boundary data
- Ignoring coordinate system mismatches
- Treating OpenStreetMap as authoritative for all features
- Failing to document data dates

## Ethical considerations

Use open data under license terms. Respect attribution. Do not use geospatial data for targeting.

## Security boundaries

No use of classified geospatial data. No high-precision data collection that could enable harm.

## Expected output

Geospatial analysis report with maps, datasets, analysis results, and source citations.

## Quality checklist

- [ ] Data sources documented
- [ ] Coordinate systems standardized
- [ ] Analysis validated
- [ ] Licenses respected
