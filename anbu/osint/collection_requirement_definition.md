# Collection Requirement Definition

> ANBU OSINT Division 002 — Collection Tradecraft

## Purpose

Defines procedures for writing collection requirements: the foundational document that directs all collection activity.

## Scope

All ANBU collection tasks, ensuring requirements are explicit, measurable, and actionable before collection begins.

## Intelligence objectives

- Convert analytical questions into collection requirements
- Define success criteria and scope boundaries
- Specify source classes and access constraints
- Establish collection priorities and stopping conditions

## Core concepts

- Requirement versus tasking
- Success criteria and deliverables
- Scope boundaries and exclusions
- Source class mapping
- Collection constraints: time, access, ethics

## Analytical methodology

Requirements are drafted from analytical questions. Each requirement specifies: question, scope (geographic, temporal, entity), success criteria, source classes to prioritize, access constraints, ethical boundaries, and stopping conditions. Requirements are reviewed for completeness before collection begins.

## Step-by-step workflow

1. Receive analytical question or tasking
2. Draft requirement with all fields
3. Review for completeness and feasibility
4. Approve or revise requirement
5. Hand to collection planning
6. Use as basis for gap analysis

## Data requirements

Analytical question; scope parameters; success criteria; constraints; ethical boundaries.

## Approved public sources

- Analytical tasking documents
- ANBU methodology standards
- Legal and ethical guidelines
- Prior collection logs for context

## Source verification standards

Every source is evaluated for authority, proximity to the event or subject, currency, and internal consistency before its content is used analytically. Primary sources are preferred over secondary accounts. Where sources conflict, the conflict is preserved and reported rather than silently resolved. Source reliability is rated on the ANBU reliability scale and recorded in the collection log.

## Analytical framework

Requirements are graded by completeness: question clarity, scope precision, success criteria measurability, and constraint explicitness. Incomplete requirements are returned for revision before collection.

## Evidence requirements

Every analytical claim must be traceable to a logged collection item. Evidence requirements: (1) verbatim quotation or precise paraphrase with page/section reference; (2) source attribution including URL or archive identifier; (3) collection timestamp; (4) access method; (5) confidence grade per the ANBU scale. Claims without logged evidence are marked INSUFFICIENT and excluded from analytical products.

## Confidence assessment

HIGH: multiple independent primary sources, direct documentation, no material contradictions. MODERATE: credible sources with minor gaps or single-source primary documentation. LOW: indirect, derivative, or partially corroborated reporting. INSUFFICIENT: evidence does not support a judgment; collection gap or contested sources prevent assessment.

## Common analytical mistakes

- Vague or unmeasurable success criteria
- Missing scope boundaries
- Ignoring access constraints
- Failing to specify stopping conditions

## Ethical considerations

Requirements must include ethical boundaries. Collection cannot proceed without explicit ethical scope.

## Security boundaries

Requirements must prohibit unlawful collection methods explicitly.

## Expected output

Collection requirement document with all fields specified and approved.

## Quality checklist

- [ ] Question clear
- [ ] Scope defined
- [ ] Success criteria measurable
- [ ] Constraints specified
- [ ] Ethics included
