# ANBU Capability Matrix

**Core Division 001 · File 008 · Classification: FOUNDATIONAL**

## Purpose

Maps what ANBU can and cannot do — by division, by confidence ceiling, and by ethical boundary. The matrix is the honest answer to "what can this system deliver?"

## Scope

Capability claims only. It does not describe how to execute (see division files) or how to report (see `output_standards.md`).

## Intelligence Objectives

- Prevent overclaiming: every advertised capability must have a defined method and evidence base.
- Let requesters calibrate expectations before commissioning work.
- Give reviewers a checklist for capability claims in products.

## Core Concepts

### Capability Classes

| Class | Definition | Confidence ceiling |
|---|---|---|
| C1 — Descriptive | What is happening, documented | HIGH achievable |
| C2 — Explanatory | Why it is happening, assessed | MODERATE typical |
| C3 — Predictive | What is likely next | MODERATE at best, short horizon |
| C4 — Prescriptive | What should be done | OUT OF SCOPE — advisory, not ANBU |

### Division Capability Summary

| Division | Strongest capability | Hard limit |
|---|---|---|
| osint/ | Source discovery & documentation | Cannot verify what it cannot reach |
| political/ | Institutional & electoral analysis | Cannot observe closed-door decisions |
| military/ | Open-source posture & procurement analysis | Cannot assess classified readiness |
| state/ | Bureaucratic & governance mapping | Cannot see informal patronage networks directly |
| geopolitical/ | Alliance & conflict dynamics | Cannot predict decisions of closed regimes reliably |
| verification/ | Provenance & authenticity grading | Cannot authenticate what leaves no trace |
| analytics/ | Structured hypothesis testing | Cannot create evidence that doesn't exist |
| geoint/ | Public imagery & terrain analysis | Limited by imagery availability and resolution |
| legal/ | Treaty & regulatory tracking | Cannot assess enforcement intent |
| security/ | Threat landscape from public indicators | Cannot assess classified threat posture |
| reporting/ | Graded, structured products | Cannot add analytical value beyond inputs |
| workflows/ | Repeatable pipelines | Cannot compensate for weak inputs |

## Analytical Methodology

Capabilities are stated as *ranges*, not points: "can assess X with MODERATE confidence under conditions Y." Unconditional capability claims are defective.

## Step-by-Step Workflow

1. Identify the requested capability class (C1–C4).
2. Check the division's capability cell.
3. Check the confidence ceiling.
4. If the request exceeds the ceiling, state the limit and offer the achievable version.

## Data Requirements

Capability claims require a named method and at least one worked example or documented procedure. Claims without methods are aspirations, not capabilities.

## Approved Public Sources

Capability is bounded by source availability. A capability requiring inaccessible data is not a capability.

## Source Verification Standards

Not applicable; this file describes system bounds.

## Analytical Framework

**Capability–Evidence Matching**: before accepting a task, match its required capability class against the matrix. C4 requests are declined; C3 requests carry mandatory uncertainty language; C1–C2 proceed normally.

## Evidence Requirements

Products must not imply capabilities beyond the matrix. A claim like "we can track this faction's financing" requires a documented method in the relevant division file.

## Confidence Assessment

- Source confidence: NOT APPLICABLE
- Information confidence: HIGH (declared bounds)
- Analytical confidence: HIGH for bounds; INSUFFICIENT where method is undocumented

## Common Analytical Mistakes

- Confusing data access with analytical capability.
- Promising prediction where only description is supportable.
- Treating the matrix as a menu rather than a boundary.

## Ethical Considerations

The matrix is an ethical instrument: it makes overclaiming visible. A system that cannot do something must say so rather than simulate it.

## Security Boundaries

Capabilities are limited to public-source analysis. No capability in this matrix authorizes operational activity, surveillance of individuals, or access to non-public systems.

## Expected Output

Capability statements in products cite the matrix class and the applicable confidence ceiling.

## Quality Checklist

- [ ] Capability class identified
- [ ] Division cell checked
- [ ] Confidence ceiling stated
- [ ] Over-ceiling requests redirected
- [ ] No implied unauthorized capability
